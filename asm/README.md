# HomeLight firmware (AVR ASM)

Прошивка распределённого контроллера освещения: несколько плат ATtiny4313 (сборка и под ATtiny2313) делят одну карту из 64 виртуальных ламп и синхронизируют её по RS-485.

Сейчас в `main.asm` собран **ConfigId = 1 (котельная)**, slave с радио. Мастер — **ConfigId = 4 (гостиная)**.

## Сборка и прошивка

```text
./gavrasm main.asm -e -a
avrdude -c usbasp -p t4313 -U flash:w:main.hex:i -B 30
```

Фьюзы: `L:E4 H:9F E:FF` (внутренний RC 8 МГц, без CKDIV8).

Конфиг платы выбирается `ConfigId` в `main.asm`. Меняется константа — пересобирается hex.

## Железо

- MCU: ATtiny4313, **8 МГц**.
- **8 входов** выключателей (подтяжка вверх, активный низкий) на PORTA/B/D.
- **8 реле** через сдвиговый регистр: `PB6` data, `PB7` clock, `PB3` strobe. Физический порядок контактов на плате перепутан — маски `Relay0…Relay7` это компенсируют.
- **RS-485**: USART 57600 8N2, направление на `PD6`.
- **LED** на `PB4` — мигает, пока есть обмен по шине.
- **Радио** (только котельная): `PD3`, OOK ~270 мкс/бит — пульт экрана проектора (A-OK).

## Идея

Локальных «ламп платы» нет. Есть общая битовая карта на 64 лампы (`Lamp_Boileroom`, `Lamp_Living`, …). Каждая плата:

1. читает свои кнопки и меняет биты в этой карте;
2. синхронизирует карту с остальными по RS-485;
3. включает свои реле, если в карте горят «её» лампы.

Поэтому выключатель в кладовке может щёлкнуть свет в коридоре на другой плате.

## Тик ~50 Гц (Timer0 CTC)

Каждые ~20 мс:

- опрос кнопок;
- пересчёт и запись реле;
- раз в секунду — таймеры автовыключения (до 4 штук);
- на котельной — старт радиопосылки, если выставлены лампы 36–38.

Главный поток — вечный `LinkLoop` по RS-485.

## Кнопки

Без фиксации. Счётчик удержания `T1`:

| Событие | Порог | Таблица |
|---|---|---|
| короткое нажатие | ~100 мс (`ShortPress = 5`) | `ShortPressConfig` |
| короткое отпускание | < 1 с | `ShortReleaseConfig` |
| длинное нажатие | ~1 с (`LongPress = 50`) | `LongPressConfig` |
| длинное отпускание | | `LongReleaseConfig` |

Действия: OffAll / Off / On / Switch / CopyFrom / SetOffTimer / Custom (вызов кода из flash). Пример custom — свет в СУ2: если горит основной или зеркало — гасит оба, иначе включает.

## Синхронизация RS-485

Свой L2: байт режется на нибблы (`0xF0|hi` — первый, `0x00|hi` — остальные), CRC 16 бит.

L7 — обмен картой ламп:

- мастер шлёт `0xAB` + DeviceId + `LampStateKnown` + 8 байт состояния;
- слейв отвечает `0xCD` + то же со своей стороны.

Мастер (гостиная) по кругу опрашивает id 0…6. Id 0 зарезервирован под компьютер — тот же протокол слушает Go-демон и ходит в MQTT. Если за ~4 с никто не разметил состояние, мастер ставит `LampStateKnown = 1`.

Конфликт локальных нажатий и чужого стейта решается масками `LampStateMaskOn` / `LampStateMaskOff`: после копирования чужой карты локальные On/Off накатываются снова.

LED: флаг `Communicated` + toggle `PINB` каждые 8 тиков.

## План изменения протокола

Сейчас мастер один и прошивается условной компиляцией (`ConfigId_Master = 4`). Если гостиная молчит, остальные платы не общаются друг с другом.

Идея: фиксированного мастера нет. Право передачи — токен, он ходит по кругу `ConfigId`. Кто держит токен, тот временно мастер.

### Выбор первого мастера

После старта (и после исчезновения мастера с шины) все молчат и слушают.

Таймаут тишины: **300 мс + 50 мс × ConfigId**. У кого меньше id — раньше начинает передачу. Остальные, услышав пакет, сбрасывают свой таймаут: мастер уже есть, самим лезть не надо.

Так первое живое устройство становится мастером. Роль временная.

### Передача токена

Мастер шлёт своё состояние **следующему** id: `ConfigId + 1` (после максимума — на минимум, по кругу).

Дальше слушает шину **50 мс**:

- адресат принял стейт, сам стал мастером и **передал состояние уже следующему** — токен ушёл, прежний мастер снова только слушает;
- за 50 мс следующего пакета нет — адресат мёртв или не услышал. Текущий мастер шлёт тому же стейт уже `ConfigId + 2`, снова ждёт 50 мс, и так далее по кругу, пока кто-то не подхватит.

Доказательство, что сосед жив — не ACK, а то, что он сам отправил пакет дальше.

### Следствия

- Все живые платы гоняют одну карту ламп, даже если гостиная выключена.
- Выпавшее устройство пропускают за 50 мс на каждый мёртвый id.
- Если с шины пропали все, снова тишина → тот же выбор мастера по 300+50×id.
- Жёсткого `ConfigId_Master` в прошивке больше нет: `link_l7_master` / `link_l7_slave` схлопываются в один код с двумя режимами (держу токен / слушаю).

Числа 300/50 мс — ориентир, не закон.

## Радио (котельная)

Виртуальные лампы:

- 36 — экран вверх
- 37 — вниз
- 38 — стоп

Если бит включили, плата 16 раз битбенгом шлёт записанный пакет (32 байта, Timer1 compare), потом гасит лампу. Сырьё пакетов собрано в `python/main.py` из протокола A-OK.

## Конфиги плат

| ConfigId | Комната | Роль |
|---|---|---|
| 0 | компьютер | слушатель шины (Go) |
| 1 | котельная | slave + радио |
| 2 | кладовка | slave |
| 3 | СУ2 | slave |
| 4 | гостиная | **мастер** |
| 5 | СУ2-упр | slave |
| 6 | детская | slave |

Таблицы реле и кнопок — в `config-vars.asm-inc`.

### Текущая прошивка (котельная)

Реле: котельная, туалет 1, бра на лестнице, фасад.

Кнопки:

- 0 — свет котельной, пока держат (On на press, Off на release);
- 1 — туалет 1, toggle;
- 2 — коридор 1 этажа;
- 7 — бра лестницы.

Радио экрана на этой плате тоже живое.
